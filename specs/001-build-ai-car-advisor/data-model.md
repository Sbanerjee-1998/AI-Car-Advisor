# Data Model: AI Car Advisor

## Durable Entities

### User

Application account and ownership root.

| Field | Type | Rules |
|---|---|---|
| `id` | UUID or integer primary key | Generated by the database |
| `name` | string | Required; bounded length |
| `email_normalized` | string | Required; lowercase/trimmed; unique |
| `password_hash` | string | Required; Argon2id output only |
| `created_at` | UTC timestamp | Required |
| `updated_at` | UTC timestamp | Updated on account changes |

The API never accepts an authoritative user ID for protected operations.

### AuthSession

Revocable server-side browser session.

| Field | Type | Rules |
|---|---|---|
| `id` | UUID or integer primary key | Generated by the database |
| `user_id` | foreign key to `User` | Required; indexed; cascade on user deletion |
| `token_hash` | string | Required; unique; never returned |
| `created_at` | UTC timestamp | Required |
| `expires_at` | UTC timestamp | Required; must be in the future when created |
| `revoked_at` | UTC timestamp nullable | Set by logout or administrative invalidation |

A session is valid only when its token hash matches, it is not revoked, and it has not expired.

### Conversation

An authenticated user's persistent chat thread.

| Field | Type | Rules |
|---|---|---|
| `id` | UUID or integer primary key | Generated by the database |
| `user_id` | foreign key to `User` | Required; indexed |
| `title` | string nullable | Derived from the first request or set by the service; bounded length |
| `created_at` | UTC timestamp | Required |
| `updated_at` | UTC timestamp | Updated when a message is persisted |

A conversation is readable, mutable, or deletable only when both its ID and current user ID match.

### Message

A visible persisted turn in a conversation.

| Field | Type | Rules |
|---|---|---|
| `id` | UUID or integer primary key | Generated by the database |
| `conversation_id` | foreign key to `Conversation` | Required; indexed; cascade on conversation deletion |
| `role` | enum | `user` or `assistant`; internal reasoning is never stored |
| `content` | text | Required; bounded request size |
| `created_at` | UTC timestamp | Required; chronological ordering |

The assistant message stores the user-safe rendered response. Structured response data may be returned to the caller but does not require a separate durable record for MVP.

### ConversationPreference

The current structured preference state for one conversation.

| Field | Type | Rules |
|---|---|---|
| `id` | UUID or integer primary key | Generated by the database |
| `conversation_id` | foreign key to `Conversation` | Required; unique one-to-one relationship |
| `budget_min_inr` | decimal nullable | Non-negative when present |
| `budget_max_inr` | decimal nullable | Non-negative and greater than or equal to minimum |
| `fuel_type` | enum nullable | Petrol, diesel, electric, hybrid, or unknown |
| `body_type` | string nullable | Normalized catalog value |
| `seating_capacity` | integer nullable | Positive when present |
| `transmission` | enum nullable | Manual, automatic, or unknown |
| `daily_distance_km` | decimal nullable | Non-negative when present |
| `usage_notes` | string nullable | Bounded length |
| `unresolved_question` | string nullable | Bounded user-safe text |
| `recent_vehicle_ids` | JSON/list nullable | Stable vehicle slugs only; bounded count |
| `updated_at` | UTC timestamp | Required |

Updates merge only newly understood values; the latest explicit preference wins. Missing values are not treated as explicit resets.

### Favourite

A user's saved vehicle reference.

| Field | Type | Rules |
|---|---|---|
| `id` | UUID or integer primary key | Generated by the database |
| `user_id` | foreign key to `User` | Required; indexed |
| `vehicle_id` | stable catalog slug | Required; indexed |
| `created_at` | UTC timestamp | Required |

Enforce a unique `(user_id, vehicle_id)` constraint. The vehicle slug must resolve through the current curated catalog before creation.

## Catalog Entity

### VehicleProfile

A read-only domain representation loaded from one curated Markdown file under `backend/data/cars/`. It is not duplicated as a full application row in SQLite.

Required stable and filterable fields include:

- `id` or `slug`
- display name, manufacturer, model year, and body type
- `fuel_type`, `transmission`, and seating capacity
- normalized `price_min_inr` and `price_max_inr`
- relevant dimensions, range/mileage, performance, safety, features, and use-case sections when known
- source document path and catalog release identifier

Missing fields remain unavailable or not applicable. The catalog adapter validates front matter and section content before ingestion and response use.

ChromaDB stores chunk-level records keyed by stable document IDs and includes the vehicle slug, section, normalized filters, and source metadata.

## Transient Response Entities

### Recommendation

Structured response item, not a durable table.

- `vehicle_id`: stable catalog slug, required and validated against retrieved evidence.
- `vehicle_name`: canonical catalog display name.
- `fit_summary`: concise user-facing explanation.
- `advantages`: bounded list.
- `considerations`: bounded list.
- `price_summary`: informational catalog value or unavailable marker.
- `specifications`: only supported catalog fields.
- `match_reasons`: structured preference matches.

### Comparison

Transient result for two or three distinct supported vehicle IDs. It contains canonical vehicle summaries, comparison dimensions, trade-offs, and a concise recommendation context. It must not invent a value when a vehicle profile lacks that field.

### FinancialEstimate

Transient result returned by the calculator service or MCP tool.

- `kind`: `emi` or `fuel_cost`
- `inputs`: normalized numeric inputs
- `result`: numeric value rounded to two decimal places
- `unit`: currency or fuel-cost period label
- `disclaimer`: estimate-only text

## Relationships and Ownership

```text
User 1---many AuthSession
User 1---many Conversation
Conversation 1---many Message
Conversation 1---one ConversationPreference
User 1---many Favourite
Favourite many---one VehicleProfile (logical catalog reference)
```

All user-owned queries include the current authenticated user ID. Messages are accessed through an owned conversation rather than by message ID alone. Deleting a conversation cascades to its messages and preference state. Deleting a user revokes or removes their sessions and owned records according to the migration policy.

## Validation and Invariants

- Emails are normalized before uniqueness checks.
- Passwords are never stored or logged in plaintext.
- Session tokens are never stored in plaintext or returned by the API.
- Conversation and favourite IDs cannot be used to access another user's records.
- A vehicle ID used by a favourite, comparison, or recommendation must resolve to a curated catalog profile.
- Recommendation fields and prices come from retrieved/catalog evidence; unsupported fields use an unavailable marker.
- EMI accepts a zero interest rate but rejects invalid loan amount, term, or negative rate inputs.
- Fuel cost rejects invalid distance, efficiency, or fuel price values.
- Input text and conversation context have bounded sizes.
- Internal prompts, tool traces, and chain-of-thought are not persisted or returned.

## State Transitions

### Authentication Session

`created -> active -> revoked` or `active -> expired`.

### Conversation

`created -> active` when a message is accepted; `active -> deleted` when the owner deletes it. Deletion removes dependent messages and preference state.

### Assistant Request

`received -> context prepared -> retrieval complete -> structured result validated -> visible assistant message persisted -> response returned`.

Validation or provider failure stops the request before an unsafe assistant result is persisted and returns a safe user-facing error. A user message may be persisted only according to the API's transaction policy; retries must not create duplicate assistant messages for the same request token if idempotency is later added.
